> R-01 Reviewer note: reliability-design.md NFR6.3 and NFR6.4 now agree. A restored waiting visit gets a new attempt, so an answer from before the restart is for an older attempt and is dropped. The 5-second timer is re-created from the visit's start time, and a visit already past 5 seconds ends as timed-out at once.

> R-02 Reviewer note: security-design.md decides a declared content script with the "run on all websites" permission, and the other design files and the contract's open question agree. The server-address permission is requested on save. A denied permission leaves the address inactive, shows an error beside the field, and ends checks in Could not check with `permission-denied`.

> R-03 Reviewer note: An address change without a reload starts a new visit and a new report (BR1.5). Forms added after the 1-second window are recorded as a known limit of the first version. That limit is a stated design decision. See the new finding on how the collector is re-triggered.

> R-04 Reviewer note: security-design.md now names an enforcing mechanism. The collector imports no settings or storage code, and a build check fails if the collector bundle contains the settings module. See the new finding on the check's reach.

> R-05 Reviewer note: traceability.json now lists all 30 requirement IDs, including NFR2.8, NFR2.9, NFR3.4 and NFR5.1 to NFR8.3. I compared the list against every ID in the nfr-requirements files and none is missing.

> R-06 Reviewer note: The NFR2.6 scan now covers the built folder, the test files and the captured debug output of a test run. The debug output is the only log that exists, because logs are console-only and never stored.

> R-07 Reviewer note: The "Other Failure Handling Added After Review" section introduces `internal-error`.
