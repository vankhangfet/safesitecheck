> R-01 Reviewer note: BR3.3 and the PageVisit state machine allow Check again from answered, timed-out and checking. Every attempt has an attemptId, and an older attempt's answer is discarded. A late answer in timed-out is ignored (BR5.2). W1 step 8 resolves the BR3.1/BR5.2 overlap.

> R-02 Reviewer note: BR8.1 makes VerdictService own per-tab state, publish `checking` on start, and let screens pull the current state. BR8.2 keeps state in session storage keyed by tab and re-checks as a new visit when it cannot be restored.

> R-03 Reviewer note: BR7.6 defines the state text and the model (setting, default jev-latest). BR6.8 defines the default Jev address and the OpenJev address requirement. It adds failureKind missing-address, restricts the key to the saved https address, and shows that address on the settings page.

> R-04 Reviewer note: BR7.5 sets a 1 second signal wait with a no-signals fallback. BR5.1 counts 5 seconds from visit start.

> R-05 Reviewer note: Userinfo stripping is fixed (BR1.3, entities). `checkable` is still imprecise in BR5.3. "Starts with http or https" would also match schemes such as `httpfoo:`. The "Edge Add-ons or Chrome Web Store sites" are not named as hosts or paths.

> R-06 Reviewer note: BR5.9 adds the unsupported-request rule. unsupported-page now appears in the entity allowed values and the Error Catalog.

> R-07 Reviewer note: The entities say there can be many verdict records per visit with one shown. BR2.2 is stated as a pure function with a fixed 0.6 starting value.
